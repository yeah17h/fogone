# 參與這個專案

> **佔位文件。** repo 尚未公開，也還沒開放外部貢獻流程。
> 公開後這份會補上實際的分支策略、review 標準與發版流程；
> 在那之前，下面這幾條是**已經定案、不會因為流程細節而改變**的部分。

## 先看這個

動手之前先讀 [`CLAUDE.md`](CLAUDE.md)。裡面有五條**架構鐵律**與一整份「已實測的環境事實」。
違反鐵律的修改一律不會被接受，不管程式碼寫得多好：

1. 免費與預設功能永不經過自家伺服器
2. 零遙測
3. 注入網頁的程式一律零框架純 DOM
4. 零破壞——只加自己的節點，不改原節點
5. 會觸發語言包下載的 `Translator.create()` 只能發生在使用者手勢內

這些不是風格偏好，是這個產品存在的理由。

## 回報問題

開 issue 時，**擴充視窗（popup）統計列的截圖比文字描述有用得多**——
它會告訴我們找到幾段、完成幾段、卡在哪一類（已是中文／非英日文／語言包未就緒），
以及語言包的實際 availability 值。這個專案零遙測，沒有遠端 log，
你的截圖就是唯一的診斷資料。

請一併附上：網址（可公開的話）、Chrome 版本、作業系統。

## 改程式的話

```bash
npm run compile   # 型別檢查，每次改完先跑
npm test          # 單元測試（分段重建、網址把關）
npm run build:test
node scripts/verify.mjs <與該修改相關的網站>   # 驗證迴圈，見 CLAUDE.md
```

**驗證迴圈不是可選的。** 這個專案的分段器與排程器改起來很容易「看起來對」，
所以每個修改都要跑一次真 Chrome 的驗證腳本，並在 PR 描述裡貼上統計數字。
`scripts/` 底下另有 PDF 與 YouTube 字幕的驗證腳本。
