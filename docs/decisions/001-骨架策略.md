# 001 骨架策略：不 fork 第三方專案，以 legacy 核心重建

- 日期：2026-11-25
- 狀態：定案（Aya 確認）

## 背景
新定位是「給中文使用者學外語，閱讀為主、學習是附帶的收穫」。依「先找開源骨架」原則，研究了 GitHub 前 5 名翻譯＋語言學習擴充功能（見 `docs/foundation-research.md` 第 3 節）。

## 考慮過的選項
| 選項 | 結果 |
|---|---|
| fork kiss-translator / FluentRead / read-frog / Yomitan | 否決：皆為 GPL-3.0，不能直接改授權為 AGPL-3.0-only；前三者另含遙測、雲端帳號或在網頁注入前端框架，違反鐵律。 |
| fork illa-helper（MIT） | 否決：Vue 3、以 LLM 改寫網頁原文 DOM（違反零破壞），沒有雙語整頁／YouTube／PDF。 |
| 以 legacy/ 核心重建 | **採用** |

## 決定
在新 repo 建立乾淨的 AGPL-3.0-only 骨架。`legacy/lib/` 中標為「直接搬」的模組原樣搬入，其餘參考後重寫（清單見 `docs/foundation-research.md` 第 1 節）。開源專案只借鏡設計思維（特別是 Yomitan 的零 DOM 修改取詞），不複製 GPL 程式碼。

## 後果
- 「重建」實際上是「舊核心搬進新架構」，約一半模組直接搬。
- 第 2 節的 28 條踩坑必須逐條繼承。
- 禁止從 GPL 專案複製程式碼片段。
